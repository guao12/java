# 龙族项目整合方案

> 对象：`D:\workSpace\java\longzu`（原型）与 `D:\workSpace\java\Dragon`（全栈项目）
> 结论先行：**这不是两个对等系统的合并，而是"原型资产下沉"** —— 以 Dragon 为主干，把 longzu 的入场体验与视觉资产收编成统一应用的一个"落地层"，其余部分舍弃。

---

## 一、两个项目的真实定位

先看清它们是什么，才谈得上怎么并。实测数据如下。

| 维度 | longzu | Dragon |
|---|---|---|
| 形态 | 单个 `index.html`（1493 行），CSS/JS 全内联 | 前端 Vue SPA + 后端 Spring Boot，两个独立工程 |
| 代码量 | 约 1090 行 CSS + 200 行 JS | 前端约 3.3 万行 / 38 个源文件 / 18 个视图；后端 13 个 Controller、17 个实体 |
| 路由 | 无。`goTo()` 手写 `display` 切换 4 个 `.page` | vue-router hash 模式，22 条路由 + 守卫 + 动态 import 分包 |
| 数据 | 无。序章文案、公告、阵营名全部硬编码 | MySQL 8 `dragon_raja` 17 张表、约 50 个 REST 端点 |
| 认证 | 无。登录按钮没有绑定任何事件 | JWT（HS256）+ BCrypt + 验证码 + 软鉴权 + 独立管理员令牌 |
| 依赖 | 0（只有 Google Fonts 外链） | 前端 4 个 dev 依赖 + 2 个运行时依赖；后端 8 类 starter |
| 资产 | 7 张 AI 生成 PNG，共 **16 MB**（单张 2–2.7 MB） | `public/` 29 个文件共 5.9 MB |
| 可运行性 | 双击即开 | 需 MySQL + 后端 + Vite 三件套 |

**读法**：longzu 是"氛围样片"，Dragon 是"能跑的产品"。longzu 里凡是**业务**的部分（登录表单、记住我、忘记密码）都是空壳；凡是**体验**的部分（徽记入场、序章打字机、阵营换背景）反而是它最有价值的东西。

项目根目录的 `AI项目生成步骤.txt` 也印证了这个时间线：第 1 步"生成一个 html 网页"，第 2 步才"把网页变成 vue 项目"。所以整合的本质是**把第 1 步的成果收回到第 2 步之后的工程里**，而不是反过来。

## 二、核心功能对照

### longzu 有什么

| 模块 | 内容 | 完成度 |
|---|---|---|
| 加载屏 | 全屏 Loading，CSS 3 秒兜底自动淡出（JS 挂了也能过） | 可用 |
| Splash 落地页 | 徽记图片 + 三重轨道环 + 光晕 + 入场动画 + 题词「凡王之血·必以剑终」 | 可用 |
| 序章 | 5 段世界观文案，逐字打字机、进度条、点击/空格推进、ESC 跳过 | 可用 |
| 门户页 | 双阵营页签（卡塞尔学院 / 蛇岐八家）切换背景图 + 组织部公告 + 登录 CTA | 可用，但纯静态 |
| 登录页 | 学号/用户名 + 密码 + 显隐 + 记住我 + 忘记密码 | **空壳**，无提交逻辑 |
| 氛围层 | 45 个 Canvas 尘埃粒子 + 18 个 DOM 尘埃 + 音乐 FAB | 粒子可用；音乐只切图标，**无音频源** |

### Dragon 有什么

| 域 | 能力 |
|---|---|
| 认证 | 注册（验证码 + 密码强度 + 后端签发学院编号）、登录（记住身份卡 / 26 小时或 7 天令牌）、密钥重置三步向导、账号探测、字典下发 |
| 论坛 | 版块 → 主题 → 楼层回复，发帖编辑器、点赞收藏、举报、游客可读（软鉴权） |
| 档案馆 | 5 个分卷（龙王 / 人物 / 武器 / 任务记录 / 言灵），分级分类检索带分面统计，四级密级按身份过滤 |
| 社交 | 好友申请 / 双向关系 / 私信 / 未读 badge 轮询 |
| 后台 | 独立登录、言灵图鉴 CRUD、主题管理（置顶/加精/下线/删除）、举报处理、数据概览 |
| 工程底座 | `R{code,message,data}` 统一响应、全局异常、JWT 拦截器、软鉴权拦截器、逻辑删除、`request.js` 请求工厂（去重 / 3 秒轻缓存 / 写操作失效 / 5xx 重试 / 401 清理）、BEM 命名 + 1446 行设计令牌 |

**能力互补关系**：longzu 提供"第一印象"，Dragon 提供"之后的一切"。两者没有一处功能真正重复——除了**登录页**和**粒子背景**这两处正面撞车。

## 三、技术栈与依赖对照

| 层 | longzu | Dragon | 是否可共存 |
|---|---|---|---|
| 运行时 | 浏览器原生 | Node 22 / JDK 21（源码 17）/ MySQL 8.0.39 | — |
| 前端框架 | 无（原生 DOM 操作） | Vue 3.5 + vue-router 4.5 | 需改写 |
| 构建 | 无 | Vite 6 + `@vitejs/plugin-vue` 5 | 需纳入 |
| 样式 | 全局 CSS + CSS 变量（自定义命名） | `theme.css` 设计令牌 + scoped | **冲突，需映射** |
| 字体 | `fonts.googleapis.com`（Cinzel / Noto Serif SC） | `fonts.googleapis.cn` 镜像（Cinzel / Inter / JetBrains Mono） | **冲突，统一走 .cn** |
| 动画 | rAF + CSS keyframes，无降级 | 全站遵守 `prefers-reduced-motion` | 需补齐 |
| 后端 | 无 | Spring Boot 3.4.5 + MyBatis-Plus 3.5.9 + jjwt 0.12.6 | 直接复用 |
| 鉴权 | 无 | JWT + 两个独立拦截器 | 直接复用 |

**依赖结论：整合不需要任何新依赖。** longzu 没有引入过 npm 包，它的能力（Canvas 粒子、打字机、CSS 动画）用现有 Vue 3 原生能力即可实现。这一点必须守住——一旦为了搬原型而引入 animation 库或图片处理库，就等于用新增技术债换视觉。

## 四、冲突清单与处置

这是整合的主要工作量所在。逐条给出现象、根因、处置。

### A. 架构冲突

| # | 冲突 | 根因 | 处置 |
|---|---|---|---|
| A1 | 入口语义打架 | Dragon 的 `/` 重定向到 `/forum`；longzu 的入口是 splash | 改 `/` 为**条件入口**：未登录首次访问 → 落地页；已登录 → `/forum` |
| A2 | 两套翻页模型 | longzu 用 `goTo()` 切 `.page.active`；Dragon 用 router + `<transition mode="out-in">` | 废弃 `goTo`，改为 3 条真实路由；注意 Dragon 的**单根节点约束**（App.vue 有自检告警，多根会白屏） |
| A3 | 两套粒子运行时 | longzu 45 个 canvas 粒子 + 18 个 DOM 尘埃；`RuneBackground.vue` 已有 800 行法阵 + 粒子 | 抽 `AmbientDust.vue` 与 RuneBackground **二选一**，落地页用尘埃、内页用法阵；离开路由必须 `cancelAnimationFrame` |
| A4 | 两套导航 | longzu 的 nav-pills 是装饰性换背景；Dragon 的 `SiteNav` 由 `data/nav.js` 驱动，12 个页面在用 | nav-pills 不进入全局导航体系，降级为落地页内部的局部控件 `FactionSwitch.vue` |
| A5 | 全局样式副作用 | longzu 有 `html, body { overflow: hidden }`、`.page`、`.fld-*`、`.btn-*` | **绝对不能整段搬**。`overflow:hidden` 会直接锁死全站所有滚动页 |

### B. 数据与内容冲突

| # | 冲突 | 处置 |
|---|---|---|
| B1 | longzu 无数据模型，序章文案、组织部公告、阵营描述全硬编码 | 序章与阵营文案进 `src/data/portal.js`（静态配置，够用）；**公告改走 `dr_notice` 表**，不要新建表 |
| B2 | 登录标识语义不同：longzu 写"学号/用户名"，Dragon 是 `account`（唯一）与 `codename`（唯一）双唯一键 | 复用现有 `POST /api/auth/login`，文案改为"学院编号 / 行动代号"，不改后端协议 |
| B3 | 门户页展示内容需遵守密级 | 若做数据化，落地页按**游客**身份请求，只出公开级；不得为了好看绕过 `SecurityLevel` |

### C. 依赖冲突

| # | 冲突 | 处置 |
|---|---|---|
| C1 | 字体源不同，`.com` 在大陆不可达 | 统一 `index.html` 已有的 `.cn` 镜像，longzu 的 `<link>` 一律丢弃 |
| C2 | longzu 无构建链，直接搬 HTML 会绕过 Vite | 全部改写为 `.vue` 组件，图片进 `public/` |
| C3 | 音乐 FAB 无音频源 | 要么接入真实 `<audio>`（并处理自动播放策略与用户手势），要么删除。**建议删除**，不做"假开关" |

### D. 样式冲突

| # | 冲突 | 处置 |
|---|---|---|
| D1 | 令牌命名与取值都不一致：`--bg-deepest` vs `--bg-0`；`--gold` 是 `#c8a56a` vs `#d8b25a`；`--serif` vs `--font-serif` | 以 `theme.css` 为准，落地页只允许用现有令牌；文档里显式禁止出现第二套 `--gold` |
| D2 | 金色差了亮度（#c8a56a 偏灰、#d8b25a 偏亮），混用会显得脏 | 统一 `#d8b25a` 系（含 `--gold-lt/-dp/-glow`），落地页的"银灰徽记"保留 `--silver` 语义单独定义 |
| D3 | longzu 无动效降级 | 落地页所有动画补 `@media (prefers-reduced-motion: reduce)` |

### E. 资源冲突

| # | 冲突 | 处置 |
|---|---|---|
| E1 | 16 MB PNG vs 现有 5.9 MB 全站资源 | 转 WebP，按 3 档尺寸出图，目标首屏图 **< 400 KB** |
| E2 | 7 张图里 **3 张从未被引用**（2 张 stone carving + 1 张 relief） | 直接不进仓库，省 7 MB |
| E3 | 文件名是 AI 提示词（`A_circular_metallic_silver_sea_2026-11-06T01-19-40.png`） | 重命名为语义名：`emblem-seal`、`story-relief`、`bg-cassell`、`bg-takamagahara` |

### F. 工程与文档冲突

| # | 冲突 | 处置 |
|---|---|---|
| F1 | 4 个 `.bat` 用 `%~dp0..\springBootTest` 相对路径硬编码 | **不建议重命名目录**。若要改成 `frontend/`+`backend/`，必须同步改 `启动.bat`/`重启.bat`/`停止.bat`/`dev-run.bat`，并重跑全部脚本 |
| F2 | 部署形态未定：hash 路由 + `base:'./'` 可静态托管，后端 `static/` 里已有一个 API 占位页 | 保持"开发分离、生产可选合并"：构建产物可拷进后端 `static/`，但需处理占位页 |
| F3 | 文档已漂移：Vue README 仍写首页是 `/home`（实际已退役重定向 `/forum`）；接口表缺论坛/好友/后台；`AI项目生成步骤.txt` 第 12 步（提示词手册）写「用户表加 permission 字段 + 密码明文」，而当前实现已是 `dr_admin` 独立表 + BCrypt | 整合收口时统一修订，否则下次接手会被误导（手册是历史提示词记录，但照着它重建会写出错误的权限模型） |

## 五、目标架构

整合后仍是前后端分离，但**入口链路变成四段**，且落地层由 longzu 供血、业务层由 Dragon 供血。

```
浏览器
  │
  ├─ /            落地页（splash + 序章，来自 longzu）── 已登录则 302 到 /forum
  ├─ /portal      门户页（双阵营 + 公告 + 登录 CTA，来自 longzu）
  ├─ /login /register /forgot /console          ← 原有
  ├─ /forum /board /thread /forum/new           ← 原有（主站）
  ├─ /archive /codex /spirit /org /log          ← 原有（资料层）
  ├─ /friends                                   ← 原有（社交）
  └─ /admin/login /admin                        ← 原有（后台）
        │
        └─ /api/**  →  Spring Boot 3.4.5  →  MySQL dragon_raja（17 表）
```

目标目录（**保守方案，不改目录名**）：

```
Dragon/
├─ 整合方案.md                    ← 本文档
├─ README.md                      ← 新增：一页说清怎么跑起来
├─ 一键启动.bat                   ← 新增：编排前后端
├─ springBootTest/                ← 后端（不动结构，可选新增 PortalController）
│   ├─ sql/  src/  ...
└─ DragonRaja-Vue/                ← 前端（吸收 longzu）
    ├─ public/img/landing/        ← 新增：emblem-seal / story-relief / bg-cassell / bg-takamagahara（webp）
    └─ src/
        ├─ views/LandingView.vue      ← 新增：落地页（序章内联，不再单独一页）
        ├─ views/PortalView.vue       ← 新增：门户页
        ├─ components/AmbientDust.vue ← 新增：Canvas 粒子（可 pause，替代 longzu 全局 rAF）
        ├─ components/FactionSwitch.vue ← 新增：双阵营切换
        ├─ data/portal.js            ← 新增：阵营/序章文案
        └─ router/index.js           ← 改造：/ 条件入口 + 两条新路由
```

> 为什么序章不单独做一页：longzu 把它做成独立 `.page` 是因为没有路由；有了 router 之后，"序章"是一次性过场，塞进落地页内部（同一个路由，内部状态机 `step`）体验更连贯，也避免用户刷新后反复看序章。

## 七、关键能力保留清单

整合最容易出的事故是"为了统一而丢掉别人辛苦做出来的东西"。因此逐项确认：

**必须原样保留（longzu 侧）**
1. 徽记三重轨道环入场动画与序号式延迟
2. 序章逐字打字机的 25ms 节奏与进度条
3. 双阵营背景交叉淡入（城堡冷蓝 / 鸟居绯红）
4. 空格/回车推进、ESC 跳过的键盘流
5. 加载屏"CSS 兜底自动消失"的容错设计（JS 挂了也能进站）

**必须原样保留（Dragon 侧）**
1. JWT + 软鉴权 + 四级密级过滤
2. `request.js` 请求工厂的全部能力（去重/缓存/失效/重试/401 清理）
3. 路由守卫与 401 自动回登录并带 `redirect`
4. `prefers-reduced-motion` 降级与移动端单列自适应
5. 后台管理独立令牌与全部 CRUD
6. 启动自动补表的幂等 SQL（`CREATE TABLE IF NOT EXISTS` + `INSERT IGNORE`）

**明确不做（防止范围蔓延）**
- 不为落地页新增数据表
- 不引入动画/图片处理 npm 包
- 不重命名两个工程目录
- 不把 longzu 的假登录能力合并进 `LoginView`

## 八、实施步骤

### P0 基线固化（0.5 天）
1. 打 tag / 建分支 `feature/integrate-longzu`
2. 按现有脚本跑通前后端，确认编译、登录、论坛发帖可用
3. 记录基线：`npm run build` 产物体积、首屏 chunk、landing 图片总量（16 MB）、接口可用清单
   - 验收：基线数据写进本文档附录，后续每阶段对比

### P1 资产管线（0.5 天）
1. 4 张在用图转 WebP，出 1440 / 960 / 640 三档；3 张未用图不入库
2. 重命名语义化，落到 `public/img/landing/`
3. 落地页首屏图加 `preload`，其余 `loading="lazy"`
   - 验收：目录总体积 < 1.5 MB、首屏图 < 400 KB、视觉无损（并排比对）

### P2 组件化移植（2 天）
1. `AmbientDust.vue`：props `density/paused`，`onUnmounted` 取消 rAF，`prefers-reduced-motion` 时直接不启动
2. `ProloguePlayer.vue`：props `lines`，emit `finish`，支持跳过，纯 CSS 动画
3. `FactionSwitch.vue`：双阵营 + 背景 crossfade，键盘可切换
4. `LandingView.vue` / `PortalView.vue`：只用 `theme.css` 既有令牌，全部 `scoped`
   - 验收：单根节点（否则 App.vue 会打印"视图渲染为空"）；页面内不出现任何 `:root` 重定义

### P3 入口接线（1 天）
1. `router/index.js`：`/` 改为条件入口（未登录首次 → `/`，已登录 → `/forum`），新增 `/portal`
2. 落地页"看过"状态用 `localStorage: dr:landing-seen` 记录，二次访问直接进 `/portal`
3. 门户页登录 CTA 指向 `/login`，注册指向 `/register`；`HomeView` 退役文件顺手删除或移入 `legacy/`
4. `SiteNav` 是否需要"学院大门"入口：建议**不加**，避免一级导航塞 6 项
   - 验收：`/#/` 直达、刷新、前进后退、已登录跳过、登录成功回 `/forum` 全部正确

### P4 数据化（可选，1 天）
1. 后端新增 `PortalController`：`GET /api/portal/overview`（软鉴权，只出公开级）
2. 复用 `dr_notice` 出公告，复用 `dr_board` 出板块统计；`continue-on-error` 语义不变

## 十一、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 全局样式泄漏 | 全站滚动/布局崩坏 | 落地页所有样式 `scoped`；合并前用 `/forum` 滚动做回归 |
| 双 rAF 循环 | 低端机掉帧、风扇狂转 | 落地页卸载时 `cancelAnimationFrame`；与 RuneBackground 互斥 |
| 入口守卫写错 | 用户陷入"落地页 ↔ 登录页"死循环 | 守卫里只判断一次 `isLoggedIn()`，不做二次跳转；用 3 种身份用例回归 |

| 单根节点违规 | 白屏（App.vue 已有先例） | 开发期看控制台 `[路由自检]` 告警，P2 验收必查 |

**回滚**：整个整合在独立分支完成，`/` 的条件入口用一个开关常量 `LANDING_ENABLED` 控制。出问题把常量置 `false`，`/` 恢复重定向 `/forum`，业务层零影响。

### 与方案的三处偏离（有意为之）

1. **没有保留 1.5 秒 Loading 屏**，改为首屏入场动画直接呈现。原型的 Loading 是"纯等待"，SPA 首屏本来就要等 JS，再压一层定时器只是白屏延时；保留的是它的设计意图（首帧有内容、不做突兀的空白）。
2. **序章不单独做路由**，而是落地页内部状态机。理由是刷新/返回时不应反复看片头——这一点比"每条路由一个页面"更重要。
3. **没有引入 `LANDING_ENABLED` 常量**。回滚成本本来就很低（删 3 个文件 + 还原路由两行），加一个常量反而是多余的抽象。回滚方式改为：把 `router/index.js` 的 `/` 路由换回 `{ path: '/', redirect: '/forum' }`。
